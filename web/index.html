01 · Problem

Problem

Operating tightly coupled AI supercomputing racks requires statistical rollout gates, optimistic concurrency on host repairs, collective stall root-cause correlation, and topology-aware sub-ring placement.

Cluster Lifecycle & Availability

Overview

NitroUltraFleet models the control-plane services that keep multi-rack AI accelerator clusters healthy from firmware rollout through physical floor repair. Staged firmware waves (Canary_1Pct -> Wave_10Pct -> Wave_50Pct -> Fleet_100Pct) are gated by a Wald Sequential Probability Ratio Test (SPRT) that halts regressed builds in 59.55% fewer host checks than a fixed-horizon Z-test. Unhealthy nodes progress through an optimistic-locked SQLite WAL state machine in 0.219 ms (p50) guarded by per-rack N-k capacity budgets. For active workloads, a tabular CUSUM and directed Wait-For graph analyzer isolates root culprit ranks across 100 / 100 collective traces, while a Buddy Sub-Ring and EASY Backfill scheduler eliminates cross-spine fragmentation and cuts mean queue wait by 48.3%.

01 · BLIND FIRMWARE WAVES

Fixed Sample Windows Delay Rollback

Waiting for a fixed sample size of 192 host checks per wave exposes dozens of extra hosts to regressed NIC or hypervisor firmware before an automated rollback triggers.

02 · RACK OVER-CORDONING

Concurrent Repairs Drain Entire Racks

Without Compare-And-Swap version locking and per-rack N-k maintenance budgets, parallel health workers can cordon too many nodes in one rack or return chronically flapping hosts prematurely.

03 · COLLECTIVE TIMEOUT STORMS

One Slow Rank Triggers 16 Alerts

When a single accelerator link degrades during ring AllReduce, all peer ranks fail seconds later with barrier timeouts while naive bin-packing scatters replacement jobs across spine switches.

04 · UNSAFE FLOOR DISPATCH

Technicians Need Drain & LOTO Gates

Pulling a blade before customer workloads drain or without electrical Lockout/Tagout verification risks workload corruption and safety incidents, while FIFO ticket queues waste floor travel distance.

01 · WALD SPRT FIRMWARE CANARY ENGINE nitro_fleet/sprt_canary.py
Evaluates candidate firmware and driver updates sequentially across Canary_1Pct -> Wave_10Pct -> Wave_50Pct -> Fleet_100Pct, halting regressed builds as soon as failure evidence crosses the upper log-likelihood boundary instead of waiting for a fixed sample window.
SPRTCanaryEngine computes exact Wald thresholds A = ln((1 - beta) / alpha) = +3.8918 and B = ln(beta / (1 - alpha)) = -3.8918 for p0 = 0.01, p1 = 0.06, alpha = 0.02, beta = 0.02. Across 500 Monte Carlo trials, SPRT needed 97.09 mean checks overall and 77.66 checks on regressed builds vs. 192 fixed Z-test checks (59.55% sample reduction on regressions).
02 · SQLITE WAL CAS REPAIR & N-K RACK GUARD nitro_fleet/repair_state_machine.py
Tracks 32 UltraServer hosts across 4 racks through HEALTHY -> SUSPECT_CORDONED -> SOFT_RESET_TRIAL -> DC_RMA_DISPATCH -> BURN_IN_QUALIFICATION -> HEALTHY while preventing concurrent split-brain updates, rack over-draining, and premature capacity return.
transition_host() executes inside BEGIN IMMEDIATE with SQLite WAL, enforcing WHERE host_id = ? AND version = ? (20 / 20 6-worker CAS races won by a single thread, 0.219 ms p50), per-rack max_unavailable_per_rack = 2 checks (8 / 8 over-budget cordons blocked), SHA-256 transition chaining (0.618 ms verify), and serpentine aisle routing (52.41% walk saved).
03 · CUSUM + WAIT-FOR & SUB-RING SCHEDULER nitro_fleet/topology_scheduler.py
Separates the single degraded rank or multi-rank deadlock cycle from downstream blocked peers during collective communication, then schedules incoming training gangs onto contiguous healthy intra-rack sub-rings around cordoned hosts.
analyze_collective_trace() combines robust warmup median/MAD normalization, tabular upper CUSUM (k = 0.5, h = 4.5), sink reachability, and Tarjan strongly connected components (100 / 100 trace accuracy in 0.351 ms p50). schedule_workload_queue() pairs aligned power-of-two Buddy Sub-Rings with EASY shadow-time backfill (0 cross-spine splits across 720 jobs vs. 292 under Naive FIFO).
04 · SOP-GROUNDED BEDROCK RMA COPILOT & API nitro_fleet/rma_copilot.py · server.py
Generates concise floor technician repair briefs and firmware rollback instructions with Amazon Bedrock while enforcing hard deterministic gates on workload drain status, rack capacity floors, and electrical Lockout/Tagout sign-off.
RMACopilot.synthesize_ticket() retrieves the matching hardware runbook (SOP-HBM-ECC-01 through SOP-CANARY-SPRT-04), evaluates evaluate_deterministic_guardrails() before calling us.amazon.nova-lite-v1:0 via Converse API (1,193.4 ms p50 across 8 / 8 passing cases), and runs regex entity grounding (0 hallucinated host or SOP IDs).
04 · Trade-Offs

Trade-Offs

Every control-plane mechanism in NitroUltraFleet balances statistical sensitivity, rack availability floors, ring contiguity, and serverless operating cost.

Architectural Decisions
01 · WALD SPRT VS FIXED-HORIZON Z-TEST

Variable Wave Duration vs. Early Regression Halt

A fixed-horizon binomial test gives a predictable wave schedule (192 checks every time) at the cost of exposing canary hosts long after a severe regression is obvious. Wald SPRT introduces variable wave duration with discrete-step boundary overshoot (3.6% empirical Type-II rate at the exact p1 = 0.06 boundary), cutting regressed build exposure by 59.55% on average and halting an 8.5% EFA CRC bug in 16 checks.

02 · STRICT N-K RACK FLOOR VS IMMEDIATE CORDON

Deferring Automated Cordons When Racks Hit Budget

Enforcing max_unavailable_per_rack = 2 on 8-host racks guarantees at least 6 healthy nodes remain online per Top-of-Rack switch, preventing correlated telemetry noise from draining a whole rack. The trade-off is that a genuine 3rd simultaneous host fault in the same rack pauses automated cordoning and pages an operator for manual capacity review.

03 · POWER-OF-TWO BUDDY RINGS VS GREEDY PACKING

Internal Ring Alignment vs. Zero Cross-Spine Penalty

Restricting gang placements to aligned 1, 2, 4, 8, 16-node Buddy Sub-Rings can hold an 8-node job briefly when 8 free slots are split across two partially cordoned racks. In exchange, it eliminates all 292 cross-spine ring fragmentations seen in Naive FIFO across 720 benchmark jobs, and EASY Backfill reclaims idle holes for short 1-node and 2-node validation runs (48.3% lower mean wait).

04 · DETERMINISTIC GATES VS AUTONOMOUS LLM ACTIONS

Hard Pre-Flight Checks Around Bedrock Ticket Synthesis

Letting an LLM decide directly whether a technician may pull a server sled risks unsafe actions under ambiguous operator notes. NitroUltraFleet evaluates host_state == DC_RMA_DISPATCH, rack N-k capacity floors, and loto_verified in sub-millisecond Python rules first, using Amazon Bedrock (1,193.4 ms p50) strictly to format grounded human-readable SOP instructions.
